### Stage 1 — Export (S1–S3; proves D4 and `export.test.ts` of D3)

- **S1 — Mapping** `scripts/tower/history.mjs`: an ES module with no I/O and no dependency, typed with JSDoc. It exports:
  - `parsePhases(text)`. It reads the first Markdown table whose header row has the cells `Task`, `Phase` and `Done`, and
    returns `{ task, phase, done }[]`, where `done` is `true` when the Done cell is `[x]`. Rows whose Task cell does not
    match `^[A-Z]{1,3}[0-9]{2,3}$` are skipped.
  - `historyEvents({ project, head, phases, reviews })`. `project` matches `^[A-Z][A-Z0-9_-]{1,31}$`, and `head` is a
    40-hex commit. `phases` is the PHASES.md text. `reviews` is `{ path, firstLine, commit, at }[]` in commit order,
    oldest first, where `commit` is 40 hex and `at` is an ISO 8601 time with an offset. The run is `import-` + the first 7
    of `head`. For each review, in order:
    - `path` must match `^docs/reviews/([A-Z]{1,3}[0-9]{2,3})-a([1-9][0-9]*)\.md$`;
    - its task must be a `parsePhases` row whose phase matches `^[A-Z][A-Z0-9-]{0,15}$`;
    - `firstLine.trim()` must be exactly `VERDICT: PASS` or `VERDICT: FAIL`.
    If any of these fails, it throws an `Error` that names the path. Otherwise it emits two events: `review` `pass`, then
    `verdict` `pass|fail`. Both carry the row's phase, the task, `at` converted to UTC as `YYYY-MM-DDTHH:MM:SSZ`, and
    `evidence` `<path>@<first 7 of commit>`. `seq` counts from 1 across the run. Keys go in contract order
    (`v, project, run, seq, phase, task, step, status, at, evidence`), with no `usage`.
  - `summary(events)` → `{ run, tasks, attempts, events }`, where `tasks` is the number of distinct tasks and `attempts`
    is events ÷ 2. `toJsonLines(events)` → one `JSON.stringify(event)` per line, each ending `\n`.
- **S2 — CLI** `scripts/tower/export-history.mjs --repo <dir> --project <KEY> [--out <file>]`. It collects through
  `execFileSync("git", ["-C", dir, …])` only, never a shell, and only these read-only commands:
  - `rev-parse HEAD` for the head;
  - `show HEAD:docs/PHASES.md` for the phases;
  - `ls-tree --name-only HEAD docs/reviews/` for the review paths;
  - per review path, `log -1 --diff-filter=A --format=%H %cI -- <path>` for the commit and its time, and
    `show HEAD:<path>` for the first line;
  - `rev-list --reverse --topo-order HEAD` to order the reviews by commit, ties by path.

  It writes `toJsonLines(...)` to `--out`, or to stdout, and prints one line to stderr:
  `export-history: run=<run> tasks=<t> attempts=<a> events=<e>`. Then it exits 0. On any failure it prints the cause to
  stderr, which may name a path but never file content beyond it, writes nothing to `--out` and exits 1. Bad or missing
  arguments print the usage and exit 2.

  `HistoryRefusal` is `"empty" | "too_many" | "json" | "contract" | "project" | "run" | "seq"`. The text is split on `\n`,
  each line drops a final `\r`, and one final empty line is allowed. The first failing line wins, numbered from 1:
  - no line gives `empty` at line 1;
  - line 5 001 gives `too_many`;
  - then, per line: `JSON.parse` fails → `json`; `parseStepEvent` returns null → `contract`; `project ≠ key` → `project`;
    a run that does not match `^import-[0-9a-f]{7,40}$`, or differs from line 1's run → `run`; a repeated `seq` → `seq`.

    `"unavailable"`.

    per event, in order. It counts `stored`, `duplicate` and `conflict`. An error, a null answer or any other `result`
    stops it, and it returns `{ kind: "failed", line: <1-based index>, stored, duplicate, conflict }`. Otherwise it

  `importHistory(key, previous, formData): Promise<ImportState>`. It runs in this order:
  1. `await requireOwner()` first.
  2. The key matches the project pattern, and `loadImportTarget` gives a project. Otherwise it returns
