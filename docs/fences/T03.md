### Prompt (canonical)

Build the Tower's observed source. A GitHub App delivery reaches `POST /api/github/webhook`. Its HMAC is checked
on the raw body, it is deduplicated by delivery id, and it becomes one `observations` row, origin observed, but
only for a registered repository. No page, no copy, no verification (`verify_reported_events` is T06), no
reconcile (M5). ADR-003 lists conclusion, PR number and labels, and DATA_MODEL §2.8 does not. DATA_MODEL wins
on precedence (`docs/reviews/T02-a2.md` row d): add no such column, and fold the conclusion into `state` (S3).

#### Steps

- **S1 — Migration** `supabase/migrations/<14-digit UTC timestamp after 20261017074305>_webhook_schema.sql`, plus
  `supabase/down/<same name>` that drops everything in reverse order. Fully qualified names throughout.
  - `public.webhook_deliveries`: `delivery_id text primary key`, `event_name text not null`,
    `received_at timestamptz not null default pg_catalog.now()`.
  - `public.observations`: `id bigint generated always as identity primary key`; `project_id uuid not null
    references public.projects (id) on delete cascade`; `sha text not null check (sha ~ '^[0-9a-f]{40}$')`;
    `kind text not null check (kind in ('workflow_run', 'check_run', 'status', 'pull_request'))`;
    `context text`; `state text not null`; `at timestamptz not null`; `received_at timestamptz not null default
    pg_catalog.now()`; `actor_login text`; `payload_ref text not null` (the delivery id). Index on
    `observations (project_id, sha)`.
  - `enable row level security` on both. Exactly two new policies, `to authenticated` only:
    `webhook_deliveries_owner_select` and `observations_owner_select`, each `for select using (public.is_owner())`.
  - `revoke insert, update, delete, truncate on public.webhook_deliveries, public.observations from anon,
    authenticated;`
  - No function, trigger or view.
- **S2 — Types.** With the local stack reset: `supabase gen types typescript --local >
  src/lib/supabase/database.types.ts`.
- **S3 — `src/lib/contract/observation.ts`** (pure, no I/O). Export the type `WebhookObservation` = `{ kind:
  "workflow_run" | "check_run" | "status" | "pull_request"; repository: string; sha: string; context: string |
  null; state: string; at: string; sender: { id: string; login: string; bot: boolean } }`. Export
  `parseWebhookObservation(eventName: string, payload: unknown): WebhookObservation | null`, which maps:

  | `eventName` | `sha` | `context` | `state` | `at` |
  |---|---|---|---|---|
  | `status` | `sha` | `context` | `state` | `updated_at` |
  | `check_run` | `check_run.head_sha` | `check_run.name` | `check_run.conclusion` if a string, else `check_run.status` | `check_run.completed_at` if a string, else `check_run.started_at` |
  | `workflow_run` | `workflow_run.head_sha` | `workflow_run.name` | `workflow_run.conclusion` if a string, else `workflow_run.status` | `workflow_run.updated_at` |
  | `pull_request` | `pull_request.head.sha` | `null` | `merged` if `pull_request.merged === true`, else `pull_request.state` | `pull_request.updated_at` |

  For every kind, `repository` = `repository.full_name`, `sender.id` = `String(sender.id)` (an integer),
  `sender.login` = `sender.login`, `sender.bot` = `sender.type === "Bot"`. It returns `null` in these cases: any
  other `eventName` (`installation`, `installation_repositories`, `ping`, …); a mapped value missing or of the
  wrong type; `sha` not matching `^[0-9a-f]{40}$`; `state` not matching `^[a-z_]{1,32}$`; an empty `context`; an
  `at` not matching `^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}(\.[0-9]+)?(Z|[+-][0-9]{2}:[0-9]{2})$`,
  or with `Date.parse` NaN. Nothing else is read or returned: no title, body, label, URL or email.
- **S4 — `src/lib/supabase/server/webhook.ts`** (`import "server-only"`) exports `createWebhookHandler(): (request:
  Request) => Promise<Response>`. It runs SECURITY_MODEL §3 and ADR-003, in order:
  1. Production host, the rule of `ingest.ts:30-39` written in this file: `VERCEL_ENV === "production"` and
     `host` = host of `TOWER_URL`. Otherwise, or with `TOWER_URL` unset or invalid → `404`, empty body.
  2. Read the raw body once as bytes. `X-Hub-Signature-256` must be `sha256=` + 64 lowercase hex. It must equal
     the HMAC-SHA256 of those bytes keyed by `process.env.GITHUB_WEBHOOK_SECRET` (`node:crypto`), compared with
     `timingSafeEqual` on equal-length buffers. A missing header, another format, a mismatch, or the secret
     unset or empty → `401 {"error":"bad_signature"}`. Nothing is stored and no database call is made. Nothing
     is parsed before this check.
  3. `JSON.parse` of the UTF-8 body, then `parseWebhookObservation(<X-GitHub-Event>, …)`. A missing or empty
     `X-GitHub-Delivery`, a parse failure or `null` → `202 {"stored":false}`, nothing stored.
  4. Create the admin client (it throws → `500`, empty body). If the delivery id is already in
     `webhook_deliveries` → `202 {"stored":false}`.
  5. Look up the `projects` row whose `repo` equals `repository`. None → `202 {"stored":false}`, nothing stored.
  6. Insert `{ delivery_id, event_name }` into `webhook_deliveries` with `upsert(…, { onConflict: "delivery_id",
     ignoreDuplicates: true }).select("delivery_id")`. No row returned (a concurrent redelivery won) →
     `202 {"stored":false}`. Then insert one `observations` row `{ project_id, sha, kind, context, state, at,
     actor_login, payload_ref: <delivery id> }`. `actor_login` is `sender.login` when `sender.bot`, or when
     `sender.id` equals the project's `owner_github_id`; otherwise `null` (BOUNDARY_MODEL §1; `owner_allowlist`
     is read only by `is_owner()`, DATA_MODEL §2.1). If the observation insert fails, delete the delivery row
     just inserted, so a redelivery can retry, and answer `500`, empty body. On success → `202 {"stored":true}`.
  Any database error in 4–6 → `500`, empty body. Every answer carries `Cache-Control: no-store` and never
  `Set-Cookie`; JSON bodies are `application/json`. Nothing is logged (no `console.*`).
