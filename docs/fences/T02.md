    `set search_path = ''`. It returns `{"result": "stored" | "duplicate" | "conflict" | "rate_limited"}`:
    1. Raise if `src` is not `ci`, `local` or `import`, or if no project has `key = payload->>'project'`.
    2. Only when `src` is `ci` or `local`: if that project has ≥ 60 `events` with `source <> 'import'` and

    3. Upsert the run on `(project_id, run_key)`, with `runs.source = src`.
    4. `body_hash = sha256(convert_to(payload::text, 'UTF8'))`: the canonical body is the jsonb text.
    5. Insert the event `on conflict (project_id, run_id, seq) do nothing`, with `origin` `imported` for
       `import`, otherwise `reported`, and `source = src`. If it was inserted, add one `event_usage` row per
       `payload->'usage'` entry, then return `stored`.
    6. If it was not inserted: the same `body_hash` returns `duplicate`. A different one inserts one
       `event_rejections` row `duplicate_conflict` and returns `conflict`.

- **S5 — `src/lib/contract/oidc.ts`.** It exports the issuer `https://token.actions.githubusercontent.com`, the
  default key set `createRemoteJWKSet(<issuer>/.well-known/jwks)` (module level, so it is cached) and
  `verifyGithubOidc(token, { audience, jwks })`. Verification is `jwtVerify` with that issuer, `audience`, and
  `algorithms: ["RS256"]`. The result is `{ ok: true, repository, repositoryOwnerId }` or `{ ok: false, reason }`:
  - `JWTExpired`, or a failed `exp`/`nbf`/`iat` claim → `expired`;
  - a failed `iss` claim → `bad_issuer`; a failed `aud` claim → `bad_audience`;
  - any other verification error → `bad_signature`;
  - a key set that cannot be fetched (`JWKSTimeout`, network) → `unavailable` (internal, never stored).
- **S6 — `src/lib/supabase/server/ingest.ts`** (`import "server-only"`) exports `createIngestHandler(options?: {
  jwks?: JWTVerifyGetKey }): (request: Request) => Promise<Response>`. It runs SECURITY_MODEL §3, in order:
  1. `process.env.VERCEL_ENV === "production"` and the `host` header equals `new URL(process.env.TOWER_URL).host`.
     Otherwise, or with `TOWER_URL` unset or invalid → `404`, empty body.
  2. A `content-length` over 2 048, or more than 2 048 bytes read from the stream (stop reading at 2 049) →
     `413 {"error":"too_large"}`.
  3. `JSON.parse` failure or `parseStepEvent` null → `400 {"error":"schema"}`.
  4. `Authorization: Bearer <token>` missing → `no_token`. Then `verifyGithubOidc` with `audience = TOWER_URL`.
     Then the `projects` row with `key = event.project`: none, or `repo` ≠ claim `repository` →
     `repo_not_registered`; `owner_github_id` ≠ claim `repository_owner_id` → `owner_mismatch`. Each answers
     `401 {"error":"<reason>"}` and inserts one `event_rejections` row with that reason; a failed insert does
     not change the answer. `unavailable` → `503`, empty body, no row.
  5. `rpc("ingest_event", { payload: event, src: "ci" })`: `stored` → `200 {"stored":true,"duplicate":false}`;
     `duplicate` → `200 {"stored":false,"duplicate":true}`; `conflict` → `409 {"error":"duplicate_conflict"}`;
     `rate_limited` → `429 {"error":"rate_limited"}`; an RPC error → `500`, empty body.
  The admin client is created only after check 1, so a preview without `SUPABASE_SECRET_KEY` answers `404`.
  Every answer carries `Cache-Control: no-store` and never `Set-Cookie`; JSON bodies are `application/json`.
  Nothing is logged (no `console.*`).
