#### Steps

- **S1 — Data (pure).** `src/lib/portfolio/aggregate.ts`, with no I/O. It exports these types:
  - `LinkState` = `"active" | "steady" | "revise" | "waiting" | "gate" | "down" | "stale" | "silent"`.
  - `PortfolioStepEvent` = `{ key; task: string | null; phase: string | null; step; status; origin; seq: number; at;
    receivedAt }`. Times are ISO strings.
  - `PortfolioProject` = `{ key; repo; staleAfterMinutes; lastActivityAt: string | null; lastContactAt: string | null;
    latest: PortfolioStepEvent | null; freshness: "fresh" | "stale" | "none"; execution: "ci" | "local" | "import" |
    null; tasks: { passed; seen }; phase: { id; passed; seen } | null; linkState: LinkState; recent: PortfolioStepEvent[] }`.
  - `IngestionHealth` = `{ lastReceivedAt: string | null; stepEventsLastHour; deliveriesLast24h; rejectionsLast24h }`.
  - `PortfolioTotals` = `{ projects; fresh; staleOrSilent; tasksPassed; tasksSeen; measuredAttempts; byLinkState:
    Record<LinkState, number> }`.
  - `Portfolio` = `{ projects; totals; recentActivity: PortfolioStepEvent[]; health; generatedAt }`.

  `aggregatePortfolio({ projectRows, stepEventRows, runRows, measuredEventIds, deliveriesLast24h, rejectionsLast24h },
  now: Date): Portfolio` computes each project as follows:
  - `lastActivityAt` = max `at`; `lastContactAt` = max `received_at`. These are two values, never merged (GLOSSARY §2).
  - `latest` = the greatest `received_at`, with a tie going to the greatest `id`.
  - `freshness`: `none` without step events; `stale` when `now − lastContactAt` > `staleAfterMinutes` minutes; else `fresh`.
  - `execution` = `runs.source` of `latest`'s run, or `null`.
  - `tasks`: `seen` = distinct non-null `task`. `passed` = those that have a step event `verdict` · `pass`.
  - `phase`: the same counts restricted to `latest.phase`, or `null` when that phase is null.
  - `linkState`, first match wins:
    1. no step event → `silent`;
    2. freshness `stale` → `stale`;
    3. by `latest.status`: `started` → `active`; `pass` and `skipped` → `steady`; `revise` → `revise`; `fail` → `down`;
       `waiting` → `gate` when `latest.step` is `gate`, else `waiting`.
  - `recent`: the step events of `latest`'s run, by `seq` descending, at most 6.
  - Sort: projects with contact first, by `lastContactAt` descending, then the rest by `key`.

  `totals`:
  - `projects`: the project count. `fresh`: projects with freshness `fresh`. `staleOrSilent`: link state `stale` or `silent`.
  - `tasksSeen` and `tasksPassed` sum the per-project `tasks` values.
  - `measuredAttempts`: the distinct ids in `measuredEventIds`. `byLinkState`: counts per state, all eight keys present.

  `recentActivity` holds the six greatest `received_at` across projects (a tie goes to the greatest `id`), each with its
  project `key`.

  `health`:
  - `lastReceivedAt`: max `received_at` over all step events.
  - `stepEventsLastHour`: step events with `received_at` > `now` − 1 h.
  - `deliveriesLast24h` and `rejectionsLast24h`: passed through as given.
