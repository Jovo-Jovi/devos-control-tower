#### Steps

- **S1 — Baseline.** Run `pnpm guards` and record the i18n key count it prints (`K keys per locale`) in the report.
- **S2 — Split the callback (OD-07 §4, SECURITY_MODEL §3).**
  - Move the body of `src/app/auth/callback/route.ts` **unchanged** into `src/app/auth/confirm/route.ts`
    (`GET`: exchange the code, `rpc("is_owner")`, sign out on `false`, the three 303s). Delete
    `src/app/auth/callback/route.ts`.
  - New `src/app/auth/callback/confirm-target.ts`: `export function confirmTarget(search: string): string`
    returns `/auth/confirm?code=<encodeURIComponent(code)>` when `code` is present and non-empty, otherwise
    `/sign-in?reason=auth_error`. Every other parameter is dropped; no other result shape exists.
  - New `src/app/auth/callback/page.tsx` (server component, `await connection()`, reads **no**
    `searchParams`) renders the card in state `checking` (S4) and the client component
    `src/app/auth/callback/ConfirmRedirect.tsx`, which on mount calls
    `window.location.replace(confirmTarget(window.location.search))` and renders nothing.
  - `src/proxy.ts`: add `pathname === "/auth/confirm"` to `isSessionExempt`. Nothing else in the file changes.
  - `SignInButton`'s `redirectTo` stays `${window.location.origin}/auth/callback`.
- **S3 — Copy.** In `src/i18n/messages/en.json`, `signIn` gains exactly four keys: `display` = `Control Tower`,
  `redirecting` = `Opening GitHub…`, `checking` = `Checking your access…`, `anotherAccount` =
  `Use another account` (`…` is U+2026). No existing value changes. Key count becomes K + 4.
- **S4 — Layout (§4.1, §6).** `SignInCard` takes `state: "signed-out" | "denied" | "error" | "checking"`.
  - Page: canvas with `--glow-accent` and `--glow-cool` on a pseudo-element of the page (so it can fade).
    Card: `--color-surface`, `--radius-3`, `box-shadow: var(--edge)`.
  - Card content in order: the product mark (`site.productName`, `--color-accent`), an `h1` with
    `signIn.display` at `--text-6` weight 500 `--leading-tight`, one sentence, then the action.
    signed-out: `signIn.body` + button `signIn.button`. denied: button `signIn.anotherAccount`, then
    `signIn.denied` under it. error: the error sentence (as today) + button `signIn.retry`, and a 1px
    `--color-fail` hairline on the card's top edge. checking: `signIn.checking` + a hairline sweep; no button.
  - Every button is `SignInButton` (props `label`, `pendingLabel` = `signIn.redirecting`), `--color-action` /
    `--color-action-ink`, `--radius-2`. The denied and error buttons start the same OAuth flow.
  - The product mark has `view-transition-name: product-mark` through a CSS-module class; the header's mark
    in the header CSS gets the same. If `rg -n "view-transition-name" src` already names the header's mark,
    use that name for both and state it in the report.
  - Pending and checking text sit in an element with `role="status"`. The page `<title>` of `/sign-in` stays.
- **S5 — Motion (§4.1, §5).** Only `transform`, `opacity` and `clip-path`; durations, easings and distances
  only as `var(--dur-*)`, `var(--ease-*)`, `var(--stagger)`, `var(--rise)`, `var(--space-1)`.
  - First paint (every state): atmosphere fades in `--dur-slow`; card rises `--rise` + fades `--dur-slow`
    `--ease-out`; title, sentence and action stagger by `--stagger` (classes or `:nth-child`, never a
    `style` prop); everything settled ≤ 740 ms; the button takes clicks from its first frame.
  - Press → redirecting: `scale(0.98)` over `--dur-instant`; the label crossfades to `pendingLabel` with a
    three-dot sequence (`--dur-ambient` loop); both labels share one grid cell so the button's size never
    changes; the button gets `aria-busy="true"` and `disabled`. The card does not move.
  - Checking: the hairline sweep loops (`--dur-ambient`) from the start edge (mirrored under `:dir(rtl)`).
    It is truthful because the page exists only while `/auth/confirm` is pending.
  - Success: `@view-transition { navigation: auto; }` in `src/styles/global.css` unless the tree already has
    it; `::view-transition-group(product-mark)` at `--dur-slow` `--ease-in-out`; the root crossfades.
  - Denied: after first paint the card nudges two cycles of `translateX(var(--space-1))` within `--dur-base`;
    the message reveals (opacity + `clip-path`). Error: the top hairline draws from the start edge
    (`clip-path`, `--dur-base`), the sentence reveals.
  - Signed out: no change to the sign-out route; the cross-document root crossfade (old and new root at
    `--dur-base`) then the sign-in first paint.
  - `@media (prefers-reduced-motion: reduce)`: no rise, nudge, scale, stagger, sweep or travel; entrances are
    an opacity fade of `--dur-quick` or nothing; the dots and the sweep are static; the shared mark crossfades.

  - **Motion evidence (OD-07 §5)** for the five states `signed-out`, `redirecting`, `checking`, `denied`,

    settled `.devos/screens/sign-in-<state>-<width>.png`; reduced motion (context `reducedMotion: "reduce"`)
