### Prompt (canonical)

The owner cannot remove a project registered by hand today (OD-14 §1: the project TOWER, added on 2026-10-19 with no
runs, cannot be removed). This task adds **Delete project** to the page of a project that no link request points to,
confirmed by typing its key, through one owner-only database function with an audit row (OD-14 §1–§3). A project that
came from a link request keeps the panel's Delete. It also lands CF-035's missing pgTAP test and the T18 review's
carry-forward (OD-14 §8).

Rules that hold throughout:
- **Registered by hand** = a `projects` row that no `link_requests` row points to (`project_id`, any state). Only such a
  project shows the Delete project section, and only `delete_registered_project` deletes it.
- **Data.** The function is `security invoker`, `set search_path = ''`, `execute` to `service_role` only. The new table
  has RLS, one owner `SELECT` policy and no write grant to `anon` or `authenticated`. There is still no `DELETE` policy
  anywhere, and `is_owner()` stays the only `security definer` function. Every existing migration, down file and pgTAP
  file stays byte for byte.
- **Server.** The action calls `requireOwner()` before anything else, compares the typed value with the key exactly
  (no trim, case-sensitive), and reaches the service-role client only through the new server-only module. Nothing is
  logged, and no error detail reaches the page.
- **Design.** No colour, px (except `1px` hairlines, which `guard:design` allows), duration or easing outside `tokens.css`, and `tokens.css` does not change. Logical
  properties only, no `style` prop, no literal UI text in TSX. Only `transform` and `opacity` animate. Keys and
  repositories go in `<bdi>` (the `Bidi` component). Focus ring and contrast as `DESIGN_SYSTEM.md` §6.
- **No** route, dependency, header, CSP, `src/proxy.ts`, `src/lib/contract/**`, `admin.ts`, `ingest.ts`, `link.ts` or
  `link-requests.ts` change. Fixtures are synthetic.
