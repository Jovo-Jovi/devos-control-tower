### Prompt (canonical)

OD-14 §4: in each theme's energy colour (`--color-energy`), the blades, ports and tower LEDs glow neon and every project
card carries a glow layer, brighter on hover and focus, brightest when selected. Glows are outer only. `filter` and
`box-shadow` never animate: a glow brightens by the **opacity** of its own layer over `--dur-quick`. Blade states unlit
today (`down`, `stale`, `silent`, `disconnected`) gain no glow.

Rules that hold throughout:
- No raw colour, px (except `1px` hairlines), duration or easing in a component: only `var(--neon-*)` and existing
  tokens. Logical properties only, no `style` prop, no literal UI text.
- No route, dependency, header, CSP, data, catalogue or server-action change. Nothing is stored.
- `src/styles/tokens.test.ts` passes unchanged. The contrast pairs of §1 do not move.

### Stage 1 — Tokens and glow styles (proves D2, D5, D6, D7 and the existing e2e)

- **S1 — Tokens.** Append to the end of `src/styles/tokens.css` the css block of `docs/DESIGN_SYSTEM.md` §1 "Neon
  glow (OD-14, T22)" byte for byte (the lines from `/* T22 additions` to the closing `}` of `:root[data-theme="dark"]`).
  Nothing above changes.
- **S2 — Card glow.** In `ProjectCard.module.css`, for both `.mapCard` and `.listCard`: an `::after` layer that is
  absolutely positioned over the card's border box, outside the glass (no inset, no tint), `pointer-events: none`,
  `box-shadow: var(--neon-card)`, `border-radius: inherit`, `opacity: var(--neon-card-rest)`. Opacity is
  `--neon-card-hover` on `:hover` and `:focus-visible`, and `--neon-card-selected` when `[aria-pressed="true"]`. The
  selected rule comes last (or is more specific), so a selected card under the mouse or with focus stays at `1`. Only
  `opacity` transitions, over `--dur-quick` `--ease-out`. A `data-dimmed` card keeps its current dimming.
- **S3 — Blades.** In `BladeField.tsx` add, behind today's `hum | glow | pulse` path, a halo path (a new class
  `halo`) only for the states that glow now (`active`, `steady`, `revise`, `gate`, `waiting`); no halo for the
  unlit states. In `BladeField.module.css`:
  - `.halo`: stroke `var(--color-energy)` (`--color-waiting` for `gate` and `waiting`, as the glow does),
    `stroke-width: var(--neon-blade-halo-width)`, CSS `filter: blur(var(--neon-blade-halo-blur))` (static),
    opacity `var(--neon-blade-halo-opacity)`. Animation per state: `hum` for `active`, `steady`, `revise`; `pulse` for
    `waiting`; none for `gate`.
  - the existing glow path for `active`, `steady`, `revise`: `stroke-width: var(--neon-blade-width)` with CSS
    `filter: blur(var(--neon-blade-blur))`. Remove the `filter="url(#blade-glow)"` attribute from any path that now
    takes a CSS `filter`, so the two do not conflict; keep it where no CSS filter is set.
  - lit ports (`active`, `steady`, `revise`, `waiting`, `gate`): `filter: var(--neon-port)`. `down`, `stale`, `silent`
    and `disconnected` ports keep today's rules and no filter.
  - Under `prefers-reduced-motion` the halo and glow stand still (the global rule already stops `animation`).
- **S4 — LEDs.** In `Tower.module.css`, `.led` and `.moduleLed` gain `box-shadow: var(--neon-led)`. Their loops stay.
- **S5 — Stage 1 proof.** Run `pnpm typecheck`, `pnpm lint`, `pnpm test` (`Test Files  27 passed (27)`),
