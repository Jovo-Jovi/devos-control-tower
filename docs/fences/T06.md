### Prompt (canonical)

Build `/projects/[key]/usage` (SCOPE S-5): the agent usage of every attempt of one project, as each tool reported it.
It shows coverage first, then totals by agent and by model, then attempts by phase → task → run, with failed attempts
in their own table. The page sits in the T04 shell on the scene, in both themes. Rules for the whole task:
- **Data:** the only schema change is the S1 view. Every value is read through the owner's session
  (`createSessionClient()`, RLS `is_owner()`), never the service role. Numbers are shown as stored. Nothing is
  estimated, derived, priced or charted, and no total adds builder and reviewer together (OD-05 §4; SCOPE §2). A value
  the tables cannot give is `—` with the legend.
- **Terms:** an *attempt* of an agent is one `build` (builder) or `review` (reviewer) event that ended `pass`, `fail` or
  `waiting` (GLOSSARY "Coverage"). A *failed attempt* is a view row whose event status is `fail`: the agent ran and
  failed.
- **T04/T05 rules hold:**
  - no `style` prop and no colour literal in TSX;
  - durations, easings and distances from `tokens.css` only, logical properties only, and no `attr(`;
  - nothing stored in the browser, no form control, no Supabase from the browser;
  - every count goes through `formatCount` or `Counter`;
  - every fact shows its origin and age (OD-05 §2).
