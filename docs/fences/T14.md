#### Steps

- **S1 — `src/lib/site/metadata-base.ts` and `src/lib/site/metadata-base.test.ts`.** Pure function `metadataBase(raw: string | undefined): URL | undefined`:
  returns `new URL(raw.trim())` only when it parses and its protocol is `http:` or `https:`; otherwise `undefined` (empty, missing, other
  scheme, garbage). No `process.env` read inside it. The unit test covers: undefined, `""`, `"not a url"`, `"ftp://x.test"`, `"https://tower.example"`
  (→ origin `https://tower.example`), with surrounding spaces. Unit files go 18 → 19.
- **S2 — Metadata.**
  - `src/i18n/messages/en.json`: one new key `site.previewAlt` (text: `Control Tower sign-in page: a glass card over a city skyline and the planet.`). Keys 161 → 162. No other catalogue change.
  - `src/app/layout.tsx`: `generateMetadata()` adds `metadataBase: metadataBase(process.env.TOWER_URL)`, `openGraph` { `type: "website"`,
    `siteName` and `title` = `site.productName`, `description` = `site.tagline`, `images: [{ url: <imported image>, width: 1200, height: 630,
    type: "image/jpeg", alt: site.previewAlt }]` } and `twitter` { `card: "summary_large_image"`, title, description, `images` the same image with alt }.
    The image is a static `import` of `@/assets/link-preview.jpg` (Next serves it from `/_next/static/media/`); give `url` the imported `.src`.
    Keep `title` and `description` as they are. No `process.env` read other than `TOWER_URL` through the helper.
- **S3 — `scripts/site/link-preview.mjs` and `src/assets/link-preview.jpg`.** The script (Node ESM, Playwright from `devDependencies`) takes
  `--base <url>` (default `http://127.0.0.1:3100`) and `--out <path>` (default `src/assets/link-preview.jpg`); opens `/sign-in` in Chromium at
  1200×630, DPR 1, `colorScheme: "dark"`, `reducedMotion: "reduce"`, waits for `[data-sign-in-card]` and for the scene to settle (fonts ready,
  two animation frames); screenshots as JPEG, lowering `quality` from 85 in steps of 5 until the file is ≤ 300 000 bytes (fails with a clear message
  below quality 40); writes the file; prints `bytes` and `quality`. No credential, no cookie, no other URL. Then **run it** against the local production
  build (`pnpm build`, then `pnpm start --port 3100` in the background, stop it afterwards) and commit the resulting JPEG. Look at the file
  (Read it as an image) and say in the report what it shows.
- **S4 — `e2e/link-preview.spec.ts`: two tests.** (1) `Link preview tags`: a context with no cookie and `extraHTTPHeaders["user-agent"]` =
  `WhatsApp/2.23.20.0 A`; `request.get("/sign-in")` → 200; parse the HTML, take the text of `<head>…</head>`, and expect inside it:
  `property="og:type" content="website"`, `og:site_name` and `og:title` = `DEV_OS Control Tower`, `og:description`, `og:image` (the content is
  an absolute `http(s)` URL whose path starts with `/_next/static/media/`), `og:image:width` `1200`, `og:image:height` `630`,
  `og:image:type` `image/jpeg`, `og:image:alt`, `twitter:card` `summary_large_image`, `twitter:image`; and none of those tags in the part after `</head>`.
  Repeat for `/sign-in?reason=auth_error`. (2) `Link preview image`: fetch that `og:image` path with `request.get` and no cookie → 200,
  `content-type` `image/jpeg`, first bytes `ff d8 ff`, body length ≤ 300 000; and `request.get("/", { maxRedirects: 0 })` → 302 with `location` ending `/sign-in`.
  e2e goes 37 → 39. Existing specs stay unchanged.
