### Prompt (canonical)

The owner opens the Tower signed out and sees only dark. The sign-in pages follow **Auto** (the system setting),
but the switch that overrides it lives only in the signed-in top bar. Put the **existing** `ThemeSwitch` on every
sign-in state, at the foot of the page, outside the card, so the owner can choose Light or Dark before signing in.
Nothing else changes: the card's size, place, states, copy and choreography, the scene, the planet, the switch's
own code and behaviour.

- **Behaviour is OD-08 §3's:** the switch sets `data-theme` on `<html>` for the open document only. Nothing is stored
  (no cookie, browser storage, URL parameter or database value); a reload returns to Auto.
- **Rules that hold:** logical properties only; no colour, px, duration or easing in CSS outside `tokens.css`; no
  `style` prop or `.style` write; no new catalogue key and no literal UI text in TSX; only `transform` and `opacity`
  animate here; no new dependency, host, route, header or data.

- **S2 — `e2e/sign-in.spec.ts`: a new test 6, `Theme switch on sign-in`** (top level, after test 5, using the
  `browser` fixture). Tests 1–5 and every helper stay unchanged. The test:
  1. For each `path` of `"/sign-in"`, `"/sign-in?reason=not_owner"`, `"/sign-in?reason=auth_error"`: a new context
     with `colorScheme: "dark"` and no cookie; `page.goto(path, { waitUntil: "load" })`; `await settle(page)`. Then:
     - `page.getByRole("group", { name: "Theme" })` is visible, and it is inside `[data-sign-in-theme]` and **not**
       inside `[data-sign-in-card]` (`locator.evaluate` with `closest`);
     - `page.getByRole("button", { name: "Auto" })` has `aria-pressed="true"`; `<html>` has no `data-theme`; the
       computed `--color-canvas` of `document.documentElement` (trimmed) is `#050507`;
     - record `localStorage.length`, `sessionStorage.length` and the sorted cookie names of the context;
     - click **Light**: `<html>` has `data-theme="light"`, Light has `aria-pressed="true"`, `--color-canvas` is
       `#eef4fb`; click **Dark**: `data-theme="dark"`, `--color-canvas` `#050507`;
     - storage is `{ local: 0, session: 0 }` and equal to the record; cookie names equal the record; `page.url()` is
       unchanged;
     - the switch's box and the card's box (`boundingBox()` of `[data-sign-in-theme] [role="group"]` and
       `[data-sign-in-card]`) do not overlap: switch top ≥ card bottom;
     - `page.reload({ waitUntil: "load" })`: `<html>` has no `data-theme`, Auto has `aria-pressed="true"`.
  2. `request.get("/auth/callback")` (through `browser.newContext().request`, no cookie): status `200` and the body
     contains `data-sign-in-theme` and `data-theme-option="light"` (the checking state server-renders the switch;
     the page itself redirects in the browser, so it is not clicked).
  3. **Captures**, for each viewport of `VIEWPORTS`, each state of `signed-out` (`/sign-in`), `denied`
     (`/sign-in?reason=not_owner`), `error` (`/sign-in?reason=auth_error`), and each theme of `THEMES`: a context with
     that viewport, `colorScheme` the **opposite** of the theme and `reducedMotion: "reduce"` (the switch then
     changes the scene instantly); `goto`, `settle`, click the theme's button, wait for `<html>` to have that
     `data-theme`, `settle` again, then `page.screenshot` to the path `.devos/screens/t13-<state>-<theme>-<width>.png`
