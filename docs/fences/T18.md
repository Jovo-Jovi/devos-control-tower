### Prompt (canonical)

A declined request that had approved a project leaves that project **disconnected** (OD-12 §4). Its row and history
stay, and `/api/ingest` refuses its events (T17). This task:
- shows the state `disconnected` on the card, list row, blade, detail panel and project page (OD-12 §7);
- relabels the health count;
- gives the panel's `project_linked` its own message (OD-13 §5);
- proves the whole flow (OD-12 §9).

It is the gate task of G-Link-Requests.

Rules that hold throughout:
- **Disconnected** = a `link_requests` row with `state = 'declined'` and this project's `project_id`. It overrides every
  other link state. It is read through the owner's session (RLS), never the service-role client.
- It counts only under **All**, the **Projects** total, and its own row of the System overview. It is not counted in
  Fresh, Stale or silent, or any other filter.
- **Design.** No colour, px, duration or easing outside `tokens.css`, and `tokens.css` does not change. Logical
  properties only, no `style` prop, and no literal UI text in TSX. Only `transform` and `opacity` animate (§5 also
  allows `stroke-dashoffset`, `offset-distance`, `clip-path` and `mask-position`). Keys and repositories go in `<bdi>`.
  Nothing new animates: a disconnected blade is drawn like `silent`'s, static, with no particles, hum, glow or ignition.
- **No** migration, pgTAP change, route, dependency, header, CSP, `src/proxy.ts`, `src/lib/contract/**`, `ingest.ts`,
  `link.ts` or `admin.ts` change. Nothing is logged. Fixtures are synthetic.
