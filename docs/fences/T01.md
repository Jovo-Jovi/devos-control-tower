- **S3 — The denied state carries the document locale on the server (attempt 1 defect H1).** Today
  `/sign-in?reason=not_owner` answers 403 with `<html lang="" dir="">` and `DocumentLocale` patches it after
  hydration. Required: the **server HTML** of the 403 response has `lang="en" dir="ltr"` from
  `defaultLocale`/`directionOf` (never a literal), and the denied sentence is in that HTML. Find the cause
  in the Next docs (`forbidden.md`, `authInterrupts`, the root layout's `await connection()`). If, and only
  if, no documented way gives both 403 and `lang`/`dir` on the server render, HALT with the probe output
  and the doc passages — the reviewer decides. Remove `src/components/DocumentLocale.tsx` once the server
  HTML is right (no client patch of `<html>`).
- **S4 — Sign-out answers 303 (attempt 1 defect H2).** `src/app/auth/sign-out/route.ts` `POST`:
  `signOut()` on the session client, then `NextResponse.redirect(new URL("/sign-in", request.url), 303)`.
  Never `redirect()` from `next/navigation` in a Route Handler (it answers 307 and the browser re-POSTs).
  No other method is exported.
- **S5 — The proxy redirects every page, not only `/` (fence v1 defect: S6 vs D3).** `src/proxy.ts`
  refreshes the session cookie on every request, then, with **no session**, answers `302` to `/sign-in`
  for **every** path except: `/sign-in`, `/auth/callback`, `/auth/sign-out`, any path starting `/api/`
  (API routes answer for themselves: `/api/projects` → 401), `/_next/`, `/favicon.ico`. An unknown path
  without a session is therefore `302 /sign-in`, never a 404. The proxy never decides ownership — only
  `requireOwner()` does, on the server, per request. Keep the `config`-free proxy or add a `matcher`;
  either way the D3 results must hold.
- **S6 — CSP style source (review finding; SECURITY_MODEL §2 says `style-src 'self'`).** In production
  (`NODE_ENV === "production"`) the policy's style directive is exactly `style-src 'self' 'nonce-<the same
  per-request nonce>'`; development may use `style-src 'self' 'unsafe-inline'` as the Next guide shows.
  Every other directive stays as attempt 1 shipped it (`default-src 'self'; script-src 'self' 'nonce-…'
  'strict-dynamic'; img-src 'self' data: https://avatars.githubusercontent.com; connect-src 'self'
  <Supabase origin>; font-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'
  <Supabase origin>`, Supabase origin from `NEXT_PUBLIC_SUPABASE_URL`, never a literal). **Fallback:** only
  if the production pages log a style CSP violation with the nonce (e2e S8 below), use `style-src 'self'
  'unsafe-inline'` in production, and paste the violation text in the report as an **Assumption**.
- **S7 — Focus ring (review finding H4, DESIGN_SYSTEM §5).** `src/styles/global.css` `:focus-visible`:
  outline `var(--color-accent)`, `outline-offset: calc(var(--space-1) / 2)` (2px from tokens). No raw px
  beyond the existing `1px` borders.
