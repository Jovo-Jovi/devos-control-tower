- **S3 — Supabase module.** `supabase init` → `supabase/config.toml` (the module's detect file). In it:
  `[auth] enable_signup = true` (GitHub sign-up creates the owner's row once), `[auth.email] enable_signup
  = false`, `enable_confirmations = false`; `[auth.external.github] enabled = true, client_id =
  "env(SUPABASE_AUTH_GITHUB_CLIENT_ID)", secret = "env(SUPABASE_AUTH_GITHUB_SECRET)"` (names only; the
  local stack runs without them — sign-in is proven by pgTAP fixtures and e2e page states, not by a live
  GitHub round-trip). Migration `supabase/migrations/<14-digit ts>_owner_allowlist.sql`, exactly:
  ```sql
  create table public.owner_allowlist (github_id text primary key);
  alter table public.owner_allowlist enable row level security;
  revoke all on table public.owner_allowlist from anon, authenticated;

  create or replace function public.is_owner()
  returns boolean
  language sql
  stable
  security definer
  set search_path = ''
  as $$
    select exists (
      select 1
      from auth.identities i
      join public.owner_allowlist a on a.github_id = i.provider_id
      where i.user_id = auth.uid()
        and i.provider = 'github'
    );
  $$;
  revoke all on function public.is_owner() from public, anon;
  grant execute on function public.is_owner() to authenticated;
  ```
  Down file `supabase/down/<same ts>_owner_allowlist.sql` (drop function, drop table). `supabase/seed.sql`
  stays empty of real ids (a comment only). pgTAP `supabase/tests/001_owner.sql`: RLS enabled on
  `owner_allowlist`; no policy on it (`pg_policies` count 0); `anon` and `authenticated` have no privilege
  on it (`has_table_privilege`); `is_owner()` has `prosecdef = true` and `proconfig = '{search_path=}'`;
  exactly one `prosecdef` function in schema `public`; **fixture identity**: insert a user into
  `auth.users` and an `auth.identities` row (`provider 'github'`, `provider_id '424242'`), `set local role
  authenticated; select set_config('request.jwt.claims', '{"sub":"<that uuid>","role":"authenticated"}',
  true)` → `is_owner()` is **false**; `reset role; insert into public.owner_allowlist values ('424242')` →
  under the same claims `is_owner()` is **true**; a second fixture identity with `provider_id '999'` →
  false. Run `node scripts/devos/modules.mjs start` then `pnpm test:db`. Generate
  `src/lib/supabase/database.types.ts` (`supabase gen types typescript --local`).

- **S6 — Auth flow and gate.** `src/app/sign-in/page.tsx` renders three states from `?reason=`: none →
  signed-out (title, body, button); `not_owner` → denied, served with HTTP **403** (look up the current
  way to set a page's status in `node_modules/next/dist/docs/`; if the App Router cannot set 403 on a page
  render, HALT and report — the reviewer decides, the fence does not guess); `auth_error` → error with the
  retry link. `src/app/auth/callback/route.ts`: exchanges
  the code (`exchangeCodeForSession`), then `rpc('is_owner')`; false → `signOut()` + `303 /sign-in?reason=
